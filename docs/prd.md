# 官网「应用工具箱」模块 PRD

> 当前决策：万创核心改造成部署于官网服务器的 Web 工具。数据库负责持久化任务和文件元数据，Worker 负责执行 `yt-dlp`/FFmpeg。本文开头的 V2 方案为当前实施依据；文末桌面深链方案仅作为历史备选保留。

## V2：服务器 Web 版（当前生效）

### 1. 产品目标

- 官网新增独立「工具箱 / TOOLBOX」模块。
- 用户进入万创核心后，无需安装 APP，直接在浏览器提交公开媒体链接。
- 服务器完成解析、下载和转码，浏览器展示实时进度并提供结果下载。
- 数据库保存任务状态、用户/访客配额、结果文件元数据、过期时间和审计记录。
- 保留现有 Electron 桌面版，未来可作为本地隐私版或大文件增强版下载。
- 后续新增工具时沿用统一的应用目录、权限、任务、存储和状态体系。

### 2. 系统结构

```text
浏览器（官网工具箱 / 万创核心页面）
          │ 创建任务、查看状态、下载结果
          ▼
官网 API（鉴权、参数校验、限流、下载凭证）
          │
          ├──────────────► 数据库
          │                应用目录、任务、事件、文件、配额
          │
          ▼
任务队列 / Worker
  独立临时目录运行 yt-dlp、FFmpeg
          │
          ▼
临时文件存储（本机磁盘或对象存储）
          │
          └──────────────► 限时下载
```

数据库不能代替服务器执行程序：它只保存数据与状态；真正的媒体解析和处理必须由 Worker 在服务器上完成。

### 3. 页面和交互

#### 3.1 工具箱首页

- 官网桌面端和移动端导航新增「工具箱」。
- 使用响应式工具卡片展示名称、简介、平台、状态和主要操作。
- 万创核心卡片主按钮为「立即使用」，进入 `/tools/wanchuang`。
- 可保留「下载桌面版」作为次级入口，但不阻碍网页版使用。

#### 3.2 万创核心 Web 工作台

- 链接输入：粘贴、清空、解析，展示支持范围和公开链接提示。
- 媒体信息：标题、封面、时长、可用格式和清晰度。
- 下载选项：视频/音频、清晰度、容器格式、字幕等白名单选项。
- 任务进度：等待、解析、下载、转码、完成、失败、取消。
- 结果区域：安全文件名、文件体积、过期倒计时和下载按钮。
- 历史任务：登录用户可查看；匿名访客仅在当前会话内查看。
- 移动端可提交任务，并下载浏览器支持的结果文件。

#### 3.3 完整用户流程

`进入官网` → `工具箱` → `万创核心` → `粘贴公开链接` → `解析` → `选择格式` → `创建任务` → `排队/处理` → `完成` → `限时下载`

失败流程：

`解析或处理失败` → `展示可理解的错误类型` → `用户修改链接或选项` → `重试`

容量保护流程：

`达到并发/磁盘阈值` → `拒绝新任务` → `提示服务器繁忙及稍后再试`，不允许无限积压。

### 4. 服务端功能（P0）

- `POST /api/tools/wanchuang/parse`：校验并解析公开媒体链接。
- `POST /api/tools/wanchuang/jobs`：创建下载/转码任务。
- `GET /api/tools/wanchuang/jobs/:id`：查询任务状态与进度。
- `POST /api/tools/wanchuang/jobs/:id/cancel`：取消本人或当前会话任务。
- `GET /api/tools/wanchuang/files/:token`：通过短时凭证下载结果。
- Worker 使用参数数组启动 `yt-dlp`/FFmpeg，不通过 shell 拼接命令。
- 每个任务使用独立随机临时目录，结束、失败或超时后统一清理。
- 限制单 IP、单会话和单账号的请求频率、并发任务和每日额度。
- 限制单任务运行时长、最大源文件、最大结果文件和磁盘水位。
- 支持轮询进度；现有 WebSocket 基础可复用时再启用实时推送。

### 5. 数据库设计

#### `tool_apps`：工具目录

- `id`、`slug`、`name`、`description`
- `type`：`web | external-web | desktop`
- `route_url`、`download_url`、`icon_url`、`cover_url`
- `status`：`beta | stable | maintenance | coming-soon`
- `visible`、`sort_order`、`created_at`、`updated_at`

#### `tool_jobs`：处理任务

- `id`：不可预测 UUID
- `tool_slug`：首期为 `wanchuang`
- `user_id`：登录用户，可为空
- `session_id_hash`、`ip_hash`：匿名配额与滥用控制，不保存原始敏感值
- `source_url`：按隐私策略脱敏或加密保存
- `options_json`：经过白名单校验的处理选项
- `status`：`queued | parsing | downloading | processing | completed | failed | cancelled | expired`
- `progress`、`error_code`、`public_error_message`
- `created_at`、`started_at`、`finished_at`、`expires_at`

#### `tool_job_events`：任务事件

- `id`、`job_id`、`event_type`、`progress`、`message`、`created_at`
- 只记录可公开的阶段信息；底层日志写入受保护的服务端日志。

#### `tool_files`：结果文件

- `id`、`job_id`、`storage_key`、`safe_name`
- `mime_type`、`size_bytes`、`checksum`
- `download_token_hash`、`token_expires_at`
- `created_at`、`expires_at`、`deleted_at`

#### `tool_usage_daily`：配额汇总

- `date`、`subject_type`、`subject_hash`
- `jobs_created`、`jobs_completed`、`bytes_generated`、`processing_seconds`

首期可使用官网现有 Supabase/PostgreSQL。任务队列初期可用数据库行锁实现；并发和规模增长后再迁移到 Redis/BullMQ 等专用队列。

### 6. 安全与运营边界

- 只允许 `https:` 公网 URL；解析域名后阻断回环、内网、链路本地和云元数据地址，重定向后再次检查，防止 SSRF。
- 不接受任意命令参数、文件路径或输出模板；所有选项使用固定白名单映射。
- Worker 使用低权限账户，不能访问官网密钥、数据库管理凭证或其他用户目录。
- 不在 Web 版接收用户 Cookie；需要登录态或受保护内容的平台首期不支持。
- 下载凭证随机、短时有效并绑定任务，不公开服务器真实文件路径。
- 页面错误只显示错误码和友好说明，不返回堆栈、命令、服务器路径或 Cookie。
- 配置最大并发、CPU/内存限制、超时、文件体积和磁盘警戒线。
- 定时清理过期数据库记录、临时目录、结果文件和异常残留进程。
- 上线前确认服务器带宽、目标平台规则、版权提示和可接受使用政策。

### 7. 非功能性要求

- 页面初次加载不下载大型媒体处理依赖；所有重型能力只在服务端。
- 任务状态在刷新页面后可恢复，已完成文件在有效期内可继续下载。
- Worker 重启后能识别并回收中断任务，不让任务永久停留在处理中。
- 服务端同一时间运行的进程数严格受控。
- 桌面与移动浏览器均可完成基础流程。
- 关键操作具备键盘可达、清晰焦点和文字状态，不只依赖颜色。

### 8. 验收标准

1. 官网导航可以进入工具箱，并展示万创核心卡片。
2. 点击「立即使用」进入站内 Web 工作台，不要求安装客户端。
3. 用户可以提交受支持的公开链接、选择格式并创建任务。
4. 页面能显示排队、下载、转码、完成、失败和取消状态。
5. 成功任务可以通过限时链接下载，链接过期后不可继续访问。
6. 不支持或危险的 URL 在启动外部程序前被拒绝。
7. 并发、超时、文件大小、频率和磁盘保护均有自动测试或可复现验证。
8. 任务失败、取消或过期后，临时文件和数据库状态能够正确清理。
9. 后续增加第二个工具无需复制万创核心页面的基础任务、配额和文件逻辑。
10. 官网类型检查、构建及核心 API/Worker 测试通过。

### 9. 发布顺序

1. 先完成工具箱 UI 和万创核心 Web 工作台原型。
2. 从 Electron `main.js` 中拆出与 Electron 无关的媒体解析、下载和转码能力。
3. 建立数据库表、API、任务队列、Worker 和临时文件清理。
4. 在开发服务器用低并发、低文件上限完成端到端联调。
5. 部署到生产服务器，配置 `yt-dlp`/FFmpeg、进程守护、磁盘监控和反向代理。
6. 小范围开放测试，观察带宽、失败率、平均任务耗时和磁盘峰值后再扩大额度。

### 10. 当前假设

- `F:\APP\ClipHarbor` 是首个需要网页版化的万创核心应用。
- 官网生产服务器允许安装并运行 `yt-dlp`、FFmpeg 及 Node.js Worker。
- 官网现有 Supabase/PostgreSQL 可用于任务元数据；媒体文件不直接存入数据库。
- 结果文件首期保存在服务器临时目录，容量或多实例需求增长后迁移到对象存储。
- 真实服务器规格、操作系统和公网带宽尚待部署阶段核验，因此并发和文件上限必须配置化。

# 附录：桌面深链备选方案（已被 V2 取代）

## 1. 产品概述

### 1.1 背景

现有个人官网 `myself-space` 已包含自我介绍、简历、作品、AI 专区、应用技能等栏目，但缺少一个可直接承载自研应用的统一入口。用户希望在官网新增独立的「工具箱」模块，将后续开发的桌面应用或 Web 应用集中展示，并让访客通过点击卡片直接打开对应应用。

首个接入对象为 `F:\APP\ClipHarbor`。该项目是 Electron 桌面应用，安装/打包产品名为「万创核心」，当前尚未注册网页可唤起的自定义协议。

### 1.2 产品目标

- 在官网主导航新增独立「工具箱」入口，与现有内容栏目保持一致的视觉和交互语言。
- 以卡片形式展示自研应用，让访客快速理解用途、平台、版本和可用状态。
- 已安装「万创核心」的访客可从网页一键唤起桌面应用。
- 未安装或浏览器未能唤起时，提供清晰的下载/安装与再次打开路径。
- 建立配置驱动的应用目录，未来新增 APP 时只需增加应用数据和协议配置。

### 1.3 非目标（首期）

- 不在浏览器内完整运行 Electron 应用。
- 不实现跨设备远程控制本机应用。
- 不在首期建设应用商店、在线支付、评论、评分或自动更新平台。
- 不将 `VOZEB-PRO` Web 创作平台作为首个接入对象；它可在后续作为 `web` 类型应用直接跳转。

## 2. 目标用户

### 2.1 主要用户

- 访问个人官网、希望体验作者作品的访客。
- 已安装「万创核心」，希望从官网快速进入应用的用户。
- 尚未安装应用，需要先了解功能并下载安装的用户。

### 2.2 管理用户

- 官网所有者：在后台控制工具箱栏目显隐、顺序和页首文案。
- 官网所有者：维护应用名称、介绍、图标、封面、版本、平台、启动链接、下载地址和状态。

## 3. 核心方案

### 3.1 应用类型

工具箱统一支持三类应用：

1. `desktop`：桌面应用，通过自定义协议唤起，例如 `wanchuang://open`。
2. `web`：Web 应用，直接打开 HTTPS 地址。
3. `download`：暂无深链能力，仅提供安装包下载或说明页。

### 3.2 首个应用：万创核心

- 项目目录：`F:\APP\ClipHarbor`
- 产品形态：Windows Electron 桌面应用
- 展示名称：万创核心
- 英文标识：CLIP HARBOR
- 核心定位：面向公开媒体链接的并发下载与素材归集工具
- 自定义协议：`wanchuang://`
- 默认启动动作：`wanchuang://open`
- 预留带参动作：`wanchuang://open?url=<encoded-url>`
- 平台：Windows
- 首期状态：可用 / 测试接入

### 3.3 唤起机制

1. 官网点击「打开应用」。
2. 前端记录点击时间并尝试导航到 `wanchuang://open`。
3. Electron 应用在安装或启动时注册 `wanchuang` 协议。
4. 如果应用已安装，系统交由万创核心处理并将其窗口置前。
5. 官网在短暂等待后显示非阻塞式结果面板：
   - 「应用已打开」：用户可关闭提示。
   - 「没有反应？」：提供再次打开、下载安装、查看使用说明。
6. 浏览器无法可靠获知第三方桌面应用是否真正打开，因此界面不得声称百分之百检测成功，只能根据页面失焦/隐藏等信号做友好推断。

### 3.4 安全边界

- 自定义协议仅接受明确白名单动作，如 `open`、`download`、`settings`。
- 所有 URL 参数必须解析、长度限制并校验协议，仅允许 `https:`（必要时兼容可信域名的 `http:` 后再强制升级）。
- 禁止把协议参数直接拼接成命令、文件路径或 shell 调用。
- 单实例运行：第二次深链唤起时复用已有窗口，并把请求发送给现有实例。
- 官网下载地址只能来自后台受控字段，不执行访客输入。

## 5. 用户交互路径（User Flows）

### 5.1 已安装万创核心

`访问官网` → `点击“工具箱”` → `浏览万创核心卡片` → `点击“打开应用”` → `浏览器请求打开 wanchuang://` → `系统启动/聚焦万创核心` → `用户开始使用`

### 5.2 未安装万创核心

`访问工具箱` → `点击“打开应用”` → `应用未被唤起` → `页面展示“没有反应？”兜底面板` → `点击“下载安装”` → `下载并运行安装包` → `返回官网或安装完成页` → `再次点击“打开应用”`

### 5.3 浏览器询问是否允许打开外部应用

`点击“打开应用”` → `浏览器显示外部协议确认` → `用户允许` → `万创核心启动`

若用户拒绝，则官网继续保留兜底面板，不反复弹窗打扰。

### 5.4 移动端访问 Windows 应用

`手机访问工具箱` → `查看万创核心卡片` → `主按钮显示“仅支持 Windows”` → `可查看介绍或复制官网地址到电脑访问`

### 5.5 后续新增 Web 应用

`管理员新增应用配置（type=web）` → `前台生成新卡片` → `用户点击“立即使用”` → `在当前页或新标签打开 HTTPS 应用`

```ts
  downloadUrl?: string;
  detailUrl?: string;
  version?: string;
  status: "beta" | "stable" | "maintenance" | "coming-soon";
  visible: boolean;
  order: number;
};
```

首期可在官网默认数据中内置万创核心配置，并对缺失字段容错，保证旧数据无需迁移即可正常打开。

## 8. 视觉与交互规范

- 延续官网现有深色、东方文艺与轻科技质感，不另造一套 SaaS 后台风格。
- 工具卡片强调「像一件可使用的作品」，不是普通作品集缩略图。
- 品牌色只用于状态点、主操作和聚焦态；保证文字对比度。
- 卡片 hover 轻微上浮，键盘 focus 清晰可见。
- 主按钮至少 44px 高，移动端保持可点击面积。
- 尊重 `prefers-reduced-motion`，减少动效用户不执行大幅动画。
- 所有文案使用简体中文；英文只作为栏目副标题或品牌标识。

## 9. 非功能性需求

### 9.1 性能

- 工具箱代码不显著增加首屏阻塞时间。
- 图标/封面使用本地优化资源并懒加载。
- 不因深链失败阻塞页面或造成长时间白屏。

### 9.2 兼容性

- 官网支持当前主流 Chrome、Edge、Safari、Firefox。
- 深链首期重点验证 Windows 10/11 的 Chrome 与 Edge。
- 未支持自定义协议的环境必须可继续浏览官网并访问下载入口。

### 9.3 可访问性

- 所有按钮有明确可读名称和键盘操作能力。
- 状态变化通过可见文字表达，不只依赖颜色。
- 弹层具备焦点管理、Esc 关闭和语义化标题。

### 9.4 可维护性

- 栏目 key、默认顺序、前后台目录共享唯一类型来源。
- 应用卡片通过 `ToolApp[]` 渲染，避免把万创核心逻辑硬编码到页面结构。
- 自定义协议解析集中在 Electron 主进程的单一模块/函数中。

## 10. 验收标准

1. 官网桌面端和移动端导航均可进入「工具箱」。
2. 工具箱至少正确展示「万创核心」卡片及平台、状态和操作按钮。
3. Windows 已安装应用时，点击「打开应用」能够启动或聚焦万创核心。
4. 万创核心已运行时重复点击不会打开多个实例。
5. 未安装应用时，官网仍可操作，并在合理时间内展示下载兜底。
6. 非 Windows 设备不会误导用户执行不可用操作。
7. 任意畸形深链参数不会触发命令执行、任意文件打开或应用崩溃。
8. 后台可以控制工具箱栏目显隐和顺序，旧数据加载不报错。
9. `npm run lint` 与官网构建通过；Electron 可正常启动和打包。
10. 后续增加第二个应用时，只需新增应用配置和对应链接，无需复制整套页面逻辑。

## 11. 实施边界与发布顺序

### 阶段 A：官网原型与栏目骨架

- 新增工具箱栏目、万创核心卡片和唤起兜底交互。

### 阶段 C：发布闭环

- 配置真实下载地址。
- 联调官网生产域名、浏览器外部协议提示、下载与再次唤起。

## 12. 合理假设

- 本 PRD 将 `F:\APP\ClipHarbor` 认定为用户所说的首个「万创核心」桌面 APP；`F:\APP\VOZEB-PRO` 虽也使用该品牌，但属于可后续直接以 Web 应用方式接入的创作平台。
- 首期目标平台为 PC Web 官网 + Windows 桌面应用。
- 真实安装包下载 URL 尚未在当前项目中确认，因此实现时应使用明确的可配置字段，不虚构生产下载地址。
- 浏览器无法提供完全可靠的安装状态检测，因此所有反馈文案采用非确定性表述并保留人工兜底。
